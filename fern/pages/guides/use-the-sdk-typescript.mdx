title: "Using the TypeScript / JavaScript SDK"
---

This guide shows you how to install the Svix TypeScript SDK, configure the client, and perform common operations like managing applications, endpoints, and messages.

## Installation

Install the SDK from npm:

```bash
npm install svix
```

## Initialising the client

Import the `Svix` class and pass your API token. All API calls require a JWT passed as a Bearer token, which the SDK handles for you automatically.

```typescript
import { Svix } from "svix";

const svix = new Svix("YOUR_API_KEY");
```

## Regional endpoints

The SDK detects your region from the token prefix and routes requests to the correct regional API automatically. Supported regions are `us`, `eu`, `in`, `ca`, and `au`.

No extra configuration is needed — initialise the client with your token and the correct regional base URL is selected for you. (needs confirmation)

## Managing applications

Each of your customers maps to a Svix application. Create one with `application.create`, passing an `ApplicationIn` object.

```typescript
const app = await svix.application.create({ name: "my-customer-app" });
console.log(app.id); // use this app ID for subsequent calls
```

You can also retrieve or list existing applications:

```typescript
// Get a single application
const app = await svix.application.get("app_id");

// List all applications
const apps = await svix.application.list({ limit: 50 });
```



## Registering endpoints

An endpoint is the destination URL that receives webhooks for an application. Create one with `endpoint.create`. When `secret` is `null`, the secret is automatically generated, which is the recommended approach.

```typescript
const endpoint = await svix.endpoint.create("app_id", {
  url: "https://example.com/webhook",
  version: 1,
});
```

You can pass an optional idempotency key to make the request safe to retry:

```typescript
const endpoint = await svix.endpoint.create(
  "app_id",
  { url: "https://example.com/webhook", version: 1 },
  { idempotencyKey: "unique-key-for-this-request" }
);
```

To list all endpoints for an application:

```typescript
const endpoints = await svix.endpoint.list("app_id", { limit: 20 });
```



## Sending messages

A message is the webhook payload you send to all endpoints registered on an application. Use `message.create` with a `MessageIn` object.

```typescript
const message = await svix.message.create("app_id", {
  eventType: "invoice.paid",
  payload: {
    id: "invoice_123",
    status: "paid",
    amount: 4200,
  },
});
```

You can also pass an idempotency key to avoid duplicate deliveries on retries:

```typescript
const message = await svix.message.create(
  "app_id",
  {
    eventType: "invoice.paid",
    payload: { id: "invoice_123" },
  },
  { idempotencyKey: "invoice_123-paid" }
);
```



## Listing message attempts

After sending a message, you can inspect delivery attempts. Use `messageAttempt.listByMsg` to list attempts for a specific message, or `messageAttempt.listByEndpoint` to list attempts for a specific endpoint.

```typescript
// Attempts for a specific message
const attempts = await svix.messageAttempt.listByMsg("app_id", "msg_id", {
  limit: 20,
  withContent: true,
});

// Attempts for a specific endpoint
const endpointAttempts = await svix.messageAttempt.listByEndpoint(
  "app_id",
  "endpoint_id",
  {
    limit: 20,
    status: 2, // 0 = Success, 1 = Pending, 2 = Failed, 3 = Sending, 4 = Canceled
  }
);
```

Both methods support filtering by `status`, `statusCodeClass`, `channel`, `tag`, `before`, `after`, and `eventTypes`.

## SDK retry behaviour

The SDK includes built-in retry logic with a configurable retry schedule. Retries are applied automatically on transient failures, so you do not need to implement your own retry loop for standard operations.

For operations that must not be duplicated — such as creating an endpoint or sending a message — pass an `idempotencyKey` in the options object. The server uses this key to deduplicate requests, making retries safe.

### Verifying incoming webhooks

If you receive operational webhooks from Svix, use the `Webhook` class to verify the signature before processing the payload.

```typescript
import { Webhook } from "svix";

const wh = new Webhook("YOUR_WEBHOOK_SECRET");

// In your HTTP handler:
wh.verify(rawBody, {
  "svix-id": req.headers["svix-id"],
  "svix-timestamp": req.headers["svix-timestamp"],
  "svix-signature": req.headers["svix-signature"],
});
```

The `verify` method accepts both `svix-*` and `webhook-*` header variants and throws a `WebhookVerificationError` if verification fails.
