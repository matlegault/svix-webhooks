---
title: "Verifying Incoming Webhooks"
---

Verify that incoming webhook payloads were sent by Svix and have not been tampered with, using the official SDKs in all nine supported languages.

## How verification works

Every webhook Svix sends includes three headers that your receiver uses to verify the payload (needs confirmation):

- `svix-id` - a unique message ID (needs confirmation)
- `svix-timestamp` - a Unix timestamp (seconds) (needs confirmation)
- `svix-signature` - one or more HMAC-SHA256 signatures, space-separated, each prefixed with `v1,` (needs confirmation)

The signature is computed over the string `<msg-id>.<timestamp>.<payload>` using the endpoint's signing secret as the HMAC key.

The SDKs also accept the unbranded header names `webhook-id`, `webhook-timestamp`, and `webhook-signature` as a fallback, so the same verification code works with any Standard Webhooks-compatible sender.

By default, verification rejects messages whose timestamp is more than 5 minutes in the past or future. This prevents replay attacks.

## Obtaining the endpoint secret

Each endpoint has its own signing secret. You can find it in the Svix dashboard under the endpoint's details, or retrieve it via the API. The secret is a base64-encoded value prefixed with `whsec_`, for example `whsec_MfKQ9r8GKYqrTwjUPD8ILPZIo2LaLaSw`.

Pass this full string (including the `whsec_` prefix) to the `Webhook` constructor in any SDK. The SDK strips the prefix and base64-decodes the key for you.

## Verifying in TypeScript/JavaScript

```typescript
import { Webhook } from "svix";

const secret = "whsec_MfKQ9r8GKYqrTwjUPD8ILPZIo2LaLaSw";

const wh = new Webhook(secret);

// headers is the object of request headers, payload is the raw request body string
try {
  wh.verify(payload, headers);
  // Payload is authentic
} catch (err) {
  // Verification failed
}
```

The `verify` method accepts `svix-*` or `webhook-*` header names and normalizes them to lowercase internally.

## Verifying in Python

```python
from svix.webhooks import Webhook, WebhookVerificationError

secret = "whsec_MfKQ9r8GKYqrTwjUPD8ILPZIo2LaLaSw"

wh = Webhook(secret)

try:
    wh.verify(payload, headers)
    # Payload is authentic
except WebhookVerificationError:
    # Verification failed
```

The Python SDK maps `svix-id`, `svix-signature`, and `svix-timestamp` headers to their `webhook-*` equivalents before delegating to the Standard Webhooks library.

## Verifying in Go

```go
import "github.com/svix/svix-webhooks/go"

secret := "whsec_MfKQ9r8GKYqrTwjUPD8ILPZIo2LaLaSw"

wh, err := svix.NewWebhook(secret)
if err != nil {
    // handle error
}

// r is an *http.Request
err = wh.Verify(payload, r.Header)
if err != nil {
    // Verification failed
}
// Payload is authentic
```

`NewWebhook` returns an error if the secret is empty or not valid base64. `Verify` enforces the 5-minute timestamp tolerance. If you need to skip the timestamp check (not recommended), use `VerifyIgnoringTimestamp` instead.

## Verifying in Java / Kotlin

**Java (Java 11+)**

```java
import com.svix.Webhook;
import com.svix.exceptions.WebhookVerificationException;

Webhook wh = new Webhook("whsec_MfKQ9r8GKYqrTwjUPD8ILPZIo2LaLaSw");

try {
    wh.verify(payload, request.headers()); // java.net.http.HttpHeaders
    // Payload is authentic
} catch (WebhookVerificationException e) {
    // Verification failed
}
```

The Java 11 variant accepts `java.net.http.HttpHeaders` directly.

**Kotlin**

```kotlin
import com.svix.kotlin.Webhook
import com.svix.kotlin.exceptions.WebhookVerificationException

val wh = Webhook("whsec_MfKQ9r8GKYqrTwjUPD8ILPZIo2LaLaSw")

try {
    wh.verify(payload, headers) // java.net.http.HttpHeaders
    // Payload is authentic
} catch (e: WebhookVerificationException) {
    // Verification failed
}
```

The Kotlin SDK checks both `svix-*` and `webhook-*` header names, and enforces a 5-minute timestamp tolerance.

## Handling verification errors

All SDKs raise a language-appropriate error when verification fails. Common causes are (needs confirmation):

- Missing or malformed `svix-id`, `svix-signature`, or `svix-timestamp` headers - the SDK returns a "missing required headers" or "invalid headers" error.
- Timestamp outside the 5-minute window - the SDK returns a "message timestamp too old" or "message timestamp too new" error.
- Signature mismatch - the SDK returns a "no matching signature found" error, which usually means the wrong secret is configured or the raw body was modified before verification.

Always pass the **raw, unparsed request body** to `verify`. Parsing the body as JSON and re-serializing it before verification will change the byte sequence and cause a signature mismatch. (needs confirmation)

When verification fails, respond with an HTTP `400` status and do not process the payload. (needs confirmation)
