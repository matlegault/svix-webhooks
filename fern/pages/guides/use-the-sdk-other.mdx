title: "Using the C#, Ruby, PHP & Rust SDKs"
---

Install and use the official Svix SDKs for .NET, Ruby, PHP, and Rust to send webhooks and verify incoming payloads.

## C#: NuGet install and SvixClient setup

Install the Svix NuGet package into your .NET project, then create a `SvixClient` with your API token:

```csharp
using Svix;

var client = new SvixClient("YOUR_API_KEY", new SvixOptions("https://api.svix.com"));
```

`SvixClient` is the entry point for all API operations. It exposes properties such as `Application`, `Endpoint`, `Message`, `MessageAttempt`, `EventType`, and `Destination`.

Each resource method has both a synchronous and an `Async` variant. Options objects let you pass query parameters and headers such as `IdempotencyKey`. For example, `EndpointCreateOptions` accepts an `IdempotencyKey` property that is sent as the `idempotency-key` header.

## C#: sending messages and verifying webhooks

Create a message for an application:

```csharp
var msg = await client.Message.CreateAsync(
    "app_id",
    new MessageIn(eventType: "invoice.paid", payload: new { id = "evt_1", amount = 100 })
);
```

To verify an incoming webhook payload, construct a `Webhook` with the endpoint secret and call `Verify`. The secret may be prefixed with `whsec_`:

```csharp
using Svix;

var wh = new Webhook("whsec_YOUR_ENDPOINT_SECRET");
wh.Verify(payload, headers.Get);
```

`Verify` accepts either a `WebHeaderCollection` or a `Func<string?, string?>` headers provider. It checks both branded (`svix-id`, `svix-signature`, `svix-timestamp`) and unbranded (`webhook-id`, `webhook-signature`, `webhook-timestamp`) header formats, and enforces a five-minute timestamp tolerance.

If verification fails, a `WebhookVerificationException` is thrown. An empty or missing secret throws `EmptyWebhookSecretException`.

## Ruby: gem install and Svix::Client setup

Add the `svix` gem to your `Gemfile` and run `bundle install`, then create a client:

```ruby
require "svix"

svix = Svix::Client.new("YOUR_API_KEY")
```

The client exposes resource accessors including `application`, `endpoint`, `message`, `message_attempt`, and `event_type`. Each resource method maps directly to an API operation.

For example, list endpoints for an application:

```ruby
endpoints = svix.endpoint.list("app_id")
```

Create an endpoint with an idempotency key:

```ruby
ep = svix.endpoint.create(
  "app_id",
  { url: "https://example.com/webhook", version: 1 },
  { "idempotency-key" => "unique-key-123" }
)
```



## Ruby: webhook verification and error types

Verify an incoming webhook with `Svix::Webhook`:

```ruby
wh = Svix::Webhook.new("whsec_YOUR_ENDPOINT_SECRET")
wh.verify(payload, headers)
```

Verification uses HMAC-SHA256 and supports both `svix-*` and `webhook-*` header formats.

The Ruby SDK defines these error types you should handle:

- `Svix::WebhookVerificationError` — raised when signature or timestamp validation fails.
- `Svix::WebhookSigningError` — raised when signing fails.
- `Svix::EmptyWebhookSecretError` — raised when the secret is missing or empty.
- `Svix::ApiError` — raised for HTTP-level API errors.

## PHP: Composer install and Svix setup

Install the SDK via Composer (needs confirmation), then instantiate the client:

```php
use Svix\Svix;
use Svix\SvixOptions;

$svix = new Svix("YOUR_API_KEY", new SvixOptions());
```

`SvixOptions` lets you configure the server URL and other client settings. The client exposes resource objects for `Application`, `Endpoint`, `Message`, `MessageAttempt`, `EventType`, `Destination`, `Authentication`, and `Streaming`.

Verify an incoming webhook payload:

```php
use Svix\Webhook;
use Svix\WebhookVerificationException;

$wh = new Webhook("whsec_YOUR_ENDPOINT_SECRET");
$wh->verify($payload, $headers);
```



## PHP: AutoConfig and WebhookVerificationException

`AutoConfig` and `AutoConfigConsumer` simplify endpoint registration for your webhook consumers. They support both legacy (`svix-*`) and new (`webhook-*`) header formats.

When verification fails, the SDK throws `WebhookVerificationException`. Signing errors throw `WebhookSigningException`. Catch these separately from the general `ApiException` to distinguish payload verification failures from API call failures.

## Rust: Cargo dependency and SvixOptions

Add the `svix` crate to your `Cargo.toml` (needs confirmation), then build a client:

```rust
use svix::api::{Svix, SvixOptions};

let svix = Svix::new("YOUR_API_KEY".to_string(), None);
```

Pass a `SvixOptions` value to customize the server URL:

```rust
let options = SvixOptions {
    server_url: Some("https://api.svix.com".to_string()),
    ..Default::default()
};
let svix = Svix::new("YOUR_API_KEY".to_string(), Some(options));
```



## Rust: async API and feature flags

All Svix API methods in the Rust SDK are async. Access resources through methods on the `Svix` struct: `application()`, `endpoint()`, `message()`, `event_type()`, `destination()`, `authentication()`, `streaming()`, `ingest()`, `integration()`, and `connector()`.

Verify a webhook payload with `Webhook`:

```rust
use svix::webhooks::Webhook;

let wh = Webhook::new("whsec_YOUR_ENDPOINT_SECRET")?;
wh.verify(payload.as_bytes(), &headers)?;
```

Verification supports both `svix-*` and `webhook-*` header names.

Some message event subscription APIs are gated behind the `svix_beta` feature flag. Enable it in `Cargo.toml` to access those endpoints. `AutoConfig` and `AutoConfigConsumer` support both v1 (deprecated) and v2 token formats for simplified endpoint registration.
