title: "Destinations & Connectors"
---

Route webhook events to third-party services and SaaS platforms using Destinations and Connectors.

## What are Destinations?

A Destination is a target that receives webhook events from Svix. Instead of delivering to a raw HTTP endpoint, a Destination lets you route events to external services and storage systems. Each Destination has a status, a configuration specific to its type, and an optional transformation to reshape the payload before delivery.

The Go SDK exposes the following Destination-related types:

- `DestinationIn` — input model for creating a destination
- `DestinationOut` — response model returned after creation or retrieval
- `DestinationPatch` — partial update model
- `DestinationStatus` / `DestinationStatusIn` — current delivery status of a destination
- `DestinationSecretRotateOut` — result of rotating a destination's secret
- `DestinationTransformIn` / `DestinationTransformationOut` — transformation configuration

## Supported destination types

Svix supports a wide range of destination backends. The following config types are available in the Go SDK:

- **Azure Blob Storage** — `AzureBlobStorageConfigIn`, `AzureBlobStorageConfigOut`, `AzureBlobStorageConfigPatch`
- **BigQuery** — `BigQueryConfigIn`, `BigQueryConfigOut`, `BigQueryConfigPatch`
- **ClickHouse** — `ClickhouseConfigIn`, `ClickhouseConfigOut`, `ClickhouseConfigPatch`
- **Elasticsearch** — `ElasticSearchConfigIn`, `ElasticSearchConfigOut`, `ElasticSearchConfigPatch`

The CLI module also exposes a `destination_transformation` subcommand, indicating that transformations are managed separately from the destination itself.

## Creating and managing destinations via API

You interact with Destinations through the `Destination` client available in each SDK. The Go SDK includes `Destination` as a top-level resource on the `Svix` client.

The CLI exposes a `svix destination` command group for managing destinations, and a separate `svix destination-transformation` group for managing their transformations.

Example CLI commands follow the pattern:

```sh
svix destination <subcommand> [flags]
```

To manage transformations on a destination:

```sh
svix destination-transformation <subcommand> [flags]
```



## What are Connectors?

A Connector is a pre-built integration that maps Svix webhook events to a specific third-party SaaS product. Connectors are typed by `ConnectorKind` and associated with a `ConnectorProduct`, making it straightforward to wire up events to a known external service without writing custom transformation logic.

The Go SDK exposes these Connector-related types:

- `ConnectorIn` — input model for creating a connector
- `ConnectorOut` — response model returned after creation or retrieval
- `ConnectorPatch` — partial update model
- `ConnectorUpsertIn` — create-or-update model
- `ConnectorKind` — enum identifying the connector type
- `ConnectorProduct` — the target product the connector integrates with

## Configuring a connector

Several SaaS products have dedicated config types available. The following are exposed in the Go SDK:

- **Adobe Sign** — `AdobeSignConfig`, `AdobeSignConfigOut`
- **Airwallex** — `AirwallexConfig`, `AirwallexConfigOut`
- **Ascend** — `AscendConfig`, `AscendConfigOut`
- **Bitbucket** — `BitbucketConfig`, `BitbucketConfigOut`
- **Checkbook** — `CheckbookConfig`, `CheckbookConfigOut`
- **DocuSign** — `DocusignConfig`, `DocusignConfigOut`
- **Easypost** — `EasypostConfig`, `EasypostConfigOut`

Each config type carries the fields required to authenticate and route events to that specific service. You pass the appropriate config when creating a `ConnectorIn`.

## Listing and updating connectors

The `Connector` resource supports standard CRUD operations. The Go SDK exposes `Connector` as a top-level resource, and the TypeScript SDK includes it in the `javascript/src/api/` surface.

To do a partial update, use `ConnectorPatch` with only the fields you want to change. To create or update in a single call, use `ConnectorUpsertIn`.

## Using the CLI for destinations and connectors

The Svix CLI provides dedicated command groups for both resources.

```sh
# Manage destinations
svix destination <subcommand>

# Manage destination transformations
svix destination-transformation <subcommand>

# Manage connectors
svix connector <subcommand>
```



All CLI commands require authentication. You can log in with `svix login` or set the `SVIX_AUTH_TOKEN` environment variable. Configuration is stored at `~/.config/svix/config.toml`.
